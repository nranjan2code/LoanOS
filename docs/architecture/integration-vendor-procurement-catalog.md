# Integration, mock-readiness and Indian vendor procurement catalogue

Status: procurement baseline, 15 July 2026. Prices are public list prices observed on that date, exclude GST unless explicitly stated, and are not vendor quotations. A blank public price is not zero: it means the supplier requires an RFQ. Reconfirm price, regulatory eligibility, data location and product scope before contracting.

Use the [platform module integration and API map](platform-module-integration-api-map.md) to see exactly where each dependency is required across channels, LOS, decision/risk, LWS, LMS, collections, collateral, finance, compliance, partners, the enterprise platform and SaaS organisation admission.

## Executive finding

LoanOS does **not** yet have production-grade mocks for the complete system. It has a reusable mock-or-real boundary for 15 families—SMS, email, WhatsApp, bureau, V-CIP, bank-account verification, payment rail, eSign, CERSAI, FIU-IND, CIC reporting, CKYCRR reporting, Account Aggregator, escrow and core banking—with India-residency and provider-certification gates. Internal accounting, reporting, settlement and exception workflows are often much deeper than the external simulators.

Most current mocks prove synchronous initiation and a happy-path response. A procurement/UAT-grade simulator must additionally reproduce asynchronous callbacks, signatures, timeouts, retries, duplicate and out-of-order events, provider-native rejects, corrections, bulk files, reconciliation totals and deterministic replay. Direct CKYC registry operations, external CRM/HRMS/DMS, GSTN/Income Tax, CRILC/CIMS, fraud intelligence, collateral panels, insurance, courts/auction, MDM, KMS/HSM, SIEM/WORM, queues/CDC and deployment control do not yet have executable vendor adapters. Organisation admission presently uses governed evidence, local controls and injected provisioning ports—not commercial verification, contracting, billing, DNS or cloud controllers.

## Mandatory contract for every integration

Every vendor adapter and mock must implement the same minimum envelope:

1. Tenant- and purpose-scoped request; explicit consent/permitted-purpose reference where personal or bureau data is used.
2. HTTPS with mTLS where supported; OAuth2 client credentials or signed service identity; keys referenced from a KMS/vault, never stored in business records.
3. Client idempotency key, immutable request checksum, correlation ID, provider reference and versioned schema.
4. Status/read API plus HMAC/JWS/mTLS callback containing event ID, correlation ID, timestamp and replay window.
5. Bounded timeout, safe retry, circuit breaker, rate-limit handling, dead-letter queue and operator replay.
6. Daily control totals and exception reconciliation; correction/reversal lineage; checksum manifests for files.
7. India processing/storage evidence where required, retention/deletion/export evidence, incident and subprocessor notice, audit rights and exit assistance.
8. Sandbox and certification pack containing happy, reject, timeout, duplicate, out-of-order, partial, tamper, expiry and recovery cases.

The repository already supplies certification governance and a callback HMAC primitive, but callback verification is not consistently wired; notably the payment settlement endpoint currently reconciles the event without first invoking that primitive.

## Vendor RFQ sheet: mandatory price lines

Ask every shortlisted vendor to return: one-time setup; sandbox/UAT/certification; minimum monthly commitment; per-success, per-attempt and per-failure price; volume tiers; callback/status/reconciliation charge; storage and retention; egress; premium support; change request/schema upgrade; dedicated IP/VPN/mTLS/HSM; GST and pass-through statutory/network charges; SLA credits; DR environment; exit/data export; and early termination. Require prices for 10k, 100k, 1m and 10m monthly units, three-year caps, and a no-charge certification sandbox.

## Recommended procurement sequence

1. Issue one common conformance/security schedule, then separate commercial lots so no aggregator becomes irreplaceable.
2. First tender: KYC/CKYC/V-CIP/bank verification, all four CICs, one primary plus alternate AA, eSign/eStamp, payment/NACH/payout, and communications. These unblock end-to-end lending pilots.
3. In parallel with the first tender, procure organisation admission: legal/RE/representative/domain verification, signup-abuse defence, contracting, billing, tenant IdP and cloud/DNS/certificate control. These unblock safe self-service SaaS onboarding.
4. Second lending tender: CBS/GL, GSTN/tax, CIC furnishing, FIU/CERSAI/RBI reporting, fraud intelligence and enterprise platform.
5. Third tender: collateral/valuation/legal/insurance/custody, field collections/courts/auction, HR/CRM/DMS and analytics.
6. Run vendor UAT only against the same adverse conformance corpus used by mocks; activate live mode only after contract, residency, security, reconciliation, DR, exit and maker-checker certification evidence passes.

The shortlist is a market-scan starting point, not an endorsement. Regulatory access may require the adopting regulated entity to contract directly, hold membership, obtain portal/leased-line credentials or use an authorised intermediary; an API aggregator cannot substitute for that institutional permission.
