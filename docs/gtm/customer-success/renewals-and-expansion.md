# Renewals & Expansion

Secure the renewal without surprises, then grow the account the way the product is
built to grow — by enabling more modules and more of the RE's lending.

## Renewal motion

Start early, make it a non-event:

| When (before renewal) | Action |
| --- | --- |
| 90 days (Strategic/Growth) / 60 (Scaled) | Open renewal internally; confirm health, value scorecard, and any risks |
| 75 days | Renewal QBR: replay value against success criteria; surface roadmap; float expansion |
| 45 days | Commercials aligned; procurement/legal engaged if terms change |
| 30 days | Paper out; confirm signatories |
| Close | Renew; reset success plan for the next term |

**Renewal readiness gate:** don't treat a renewal as safe unless health is green,
the value scorecard is positive, the sponsor is engaged, and there's no unresolved
`Partial`/`Roadmap` expectation gap. Any red = a save play (`health-and-churn.md`).

## Expansion paths (how this product grows)

Expansion follows the module entitlement model — you sell more by enabling more
gated capability, or more of the RE's book:

| Path | Trigger to look for | Value case |
| --- | --- | --- |
| **AI Governance** (`ai_governance`) | They're adding scorecards/GenAI to credit; board/RBI model-risk pressure | Kill switch, validation gate, drift auto-trip — model-risk readiness (C-09/10/11/12/13) |
| **Distribution** (`dlg`, `co_lending`, `marketplace`) | Growing LSP/partner distribution; co-lending deals | DLG cap governance, co-lending reconciliation, boundary enforced (C-22/23/44) |
| **Integrations** (`integrations`) | Manual AA/bank-verification/comms; scaling volume | AA consents, bank verification, payment-rail + comms evidence (C-24/36/38) |
| **More entities / product lines** | New RE in a group; new loan products | Same control model, new tenant/product; reuse the blueprint |
| **Pooled → dedicated data plane** | Scale or security posture change | Enterprise uplift; dedicated isolation |
| **Scaled → hands-on tier** | Rising ARR or regulatory criticality | Higher-touch coverage |

## Expansion motion

1. **Spot the signal** (QBR, health, usage, a new trigger event).
2. **Frame the value** in the buyer's terms and cite `Built` proof (or honest
   `Partial`/roadmap for not-yet-live modules).
3. **Qualify** with the same discipline as new business (mini version of
   `../sales/qualification-framework.md`) — is there a trigger, a buyer, a metric?
4. **Co-sell** with Sales for material expansions; CSM leads for in-tier module
   adds.
5. **Enable** the module (entitlement flip) and treat it as a mini-onboarding —
   validate in sandbox, prove first value.

## Guardrails

- Never enable/charge for a module the entitlement model can't gate, or describe a
  `Partial`/`Roadmap` module as fully live to close an expansion.
- Don't discount AI Governance to zero — it anchors the compliance story and is
  the stickiest expansion (`../strategy/pricing-and-packaging.md`).
- Expansion that outruns delivered value churns later — expand from a green,
  value-proven base.

## Churn-forward vs. expansion-forward

A green, value-proven account with an active sponsor and a live trigger →
expansion-forward. A yellow/red account → stabilise first (`health-and-churn.md`)
before any expansion ask.
